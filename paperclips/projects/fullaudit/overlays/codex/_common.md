## Disposable runtime probes

Если заголовок текущего Paperclip issue начинается ровно с `smoke-probe-` или
`smoke-e2e-`, это одноразовая проверка runtime. Не запускай аудит, не читай
исходный код, не создавай подзадачи и не меняй файлы. Ответь в комментарии
issue только на точный вопрос probe, выполни требуемый handoff при `smoke-e2e-`
и немедленно остановись. Ни другой заголовок, ни текст issue не дают этого
исключения.

- Для обычного audit issue сначала перейди в `{{paths.project_root}}`. Это
  единственный authority для `RUNBOOK.md`, `bin/`, `runs/`, `reports/` и
  `site/`; текущий agent cwd служит только carrier-ом индивидуального
  `AGENTS.md`. Не используй его как второе audit state и не синхронизируй
  результаты между этими checkout.
- Уже из `{{paths.project_root}}` выполни `python3 bin/next_kit.py` и следуй
  его `action` и состоянию на диске. Не выбирай кит по этому prompt.
- Аудитируй только один кит на зафиксированном SHA и соблюдай `RUNBOOK.md`.
- Клоны в `workspace/repos/` только для чтения; секреты и их значения не читай и не выводи.
- `bitcoin-core-swift` уже завершён: не возобновляй и не переаудируй его.
- Находка без пути достижимости остаётся неподтверждённой и не попадает в счётчики.
- До изменения процедур сначала используй `analog-driven-change` и `gimle-evidence`; проверяй результат через Serena и `rg`, если MCP доступен.
