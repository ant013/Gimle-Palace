## Silent-failure spot

`Unstoppable/Unstoppable/Modules/SendNew/BitcoinSendHandler.swift`, inside `sendData(transactionSettings:)`.

When the user attempts a max-balance Bitcoin send (`decimalValue == balance`), the handler calls `adapter.availableBalance(params:)`. That wrapper, in `BitcoinBaseAdapter.swift` line 299-302, does:

```swift
func availableBalance(params: SendParameters) -> Decimal {
    let amount = (try? abstractKit.maxSpendableValue(params: params)) ?? 0
    return Decimal(amount) / coinRate
}
```

The `try?` swallows `BitcoinCoreErrors.SendValueErrors.notEnough` — thrown when the available UTXOs cannot cover even the dust + fee — and silently returns 0. The handler then sets `params.value = 0`, calls `adapter.sendInfo` which can succeed for a zero-value request, so `transactionError` stays `nil`. `SendData.canSend` becomes `false` (fee may be nil or zero) but `cautions()` returns an empty list because `transactionError == nil`. Result: the send screen disables the button with no visible reason — exactly the reported silent failure.

## Smallest patch

Detect the swallow at the only place it matters (the new-send Bitcoin handler) and synthesize the lost error so the existing `UtxoSendHelper.caution` mapper surfaces "fee_settings.errors.insufficient_balance" to the user. No protocol/API change, no other callers affected.

## Why this works

- `transactionError = BitcoinCoreErrors.SendValueErrors.notEnough` is the exact type already handled in `UtxoSendHelper.caution` (line 33-37): it maps to the localized "Insufficient balance" title and "Insufficient `<COIN>` balance" body.
- `SendData.cautions(...)` in the same file (line 114-116) already appends that caution whenever `transactionError != nil`, so the existing UI rendering path lights up — no new wiring.
- We skip the now-pointless `sendInfo` call when we already know there is no spendable amount, avoiding an avoidable RPC and a misleading zero-fee result.
- The change is localized to `BitcoinSendHandler.sendData`; no protocol changes, no other call sites of `availableBalance(params:)` touched (the only other caller is the legacy `SendBitcoinAdapterService.update(...)` which has its own `sendInfoState = .failed(error)` path already).
