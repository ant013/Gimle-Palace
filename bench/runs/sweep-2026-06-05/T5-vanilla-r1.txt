# 1Inch cross-chain swap in unstoppable-wallet-ios

## TL;DR — Important caveat

The 1Inch integration in unstoppable-wallet-ios is **single-chain only**. It does **not** perform cross-chain swaps such as "ETH on Ethereum -> BNB on BSC". The provider explicitly rejects any pair whose `tokenIn.blockchainType != tokenOut.blockchainType` (see `OneInchMultiSwapProvider.supports`, lines 34-43). For true cross-chain swaps the app routes through different providers (`ThorChainMultiSwapProvider`, `MayaMultiSwapProvider`, `AllBridgeMultiSwapProvider`).

What 1Inch DOES handle, on a single chain at a time, are the supported EVM networks: Ethereum, BNB Smart Chain, Polygon, Avalanche, Optimism, Arbitrum One, Gnosis, Fantom, Base. So an in-chain swap on Ethereum, or an in-chain swap on BNB Smart Chain, both go through the components below — just never the same swap from one chain to the other.

Supporting helpers used by the flow:
- `EvmFeeEstimator` — estimates gas for the swap tx (`OneInchMultiSwapProvider.confirmationQuote`).
- `EvmMultiSwapQuote` / `EvmSwapFinalQuote` (`Modules/MultiSwap/Providers/`) — value types that carry the quote + transaction data back to the UI/sender.
- `MultiSwapAllowanceHelper` (`Modules/MultiSwap/Providers/MultiSwapAllowanceHelper.swift`) — handles ERC-20 approval to the 1Inch router before the swap.
- `USwapMultiSwapProvider.track(...)` — analytics ping after the tx is mined (called from `OneInchMultiSwapProvider.track`).

### Quoting vs. signing vs. route-building (in one line each)
- **Quoting:** `OneInchMultiSwapProvider.quote(...)` -> `OneInchKit.Kit.quote(...)` -> 1Inch aggregator API. Returns `OneInchKit.Quote` (used to compute `EvmMultiSwapQuote.expectedBuyAmount`).
- **Route building / tx assembly:** `OneInchMultiSwapProvider.confirmationQuote(...)` -> `OneInchKit.Kit.swap(...)` returns `OneInchKit.Swap` whose `transactionData` (extension at bottom of `OneInchMultiSwapProvider.swift`) feeds `EvmSwapFinalQuote.transactionData`.
- **Signing + broadcasting:** the `EvmKitWrapper` / `EvmKit.Kit` obtained from `evmBlockchainManager.evmKitManager(blockchainType:)` — same EVM signer the rest of the app uses for sends. Driven by `MultiSwapSendHandler` via the shared confirmation/send flow.

### Why this is NOT cross-chain
`OneInchMultiSwapProvider.supports(tokenIn:tokenOut:)` returns `false` whenever the two tokens are on different blockchains. `quote` / `confirmationQuote` then take a single `chain` derived from `tokenIn.blockchainType` and the EVM signer for that one chain. A cross-chain ETH->BNB swap would therefore be routed by `MultiSwapProviderManager` to ThorChain, Maya, or AllBridge providers, not to the 1Inch one.

(There is also a legacy single-swap stack at `Modules/Swap/Adapters/OneInch/` — `OneInchModule`, `OneInchService`, `OneInchTradeService`, `OneInchProvider`, `OneInchViewModel`, `OneInchDataSource` — superseded by the MultiSwap stack above. It is also single-chain; it still wraps `OneInchKit.Kit` via the RxSwift bridge in `packages/WalletCore/.../BackCompatibility/OneInchKit.swift`.)
