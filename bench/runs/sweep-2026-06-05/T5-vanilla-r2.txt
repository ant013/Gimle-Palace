# 1Inch in unstoppable-wallet-ios: same-chain only, NOT cross-chain

## TL;DR

The unstoppable-wallet-ios codebase does **NOT** use 1Inch for cross-chain
swaps. The example in the prompt (swap a token on Ethereum for a token on
BNB Smart Chain) cannot be routed through the 1Inch provider in this app
— the `OneInchMultiSwapProvider.supports(tokenIn:tokenOut:)` method
explicitly returns `false` whenever `tokenIn.blockchainType !=
tokenOut.blockchainType`.

Cross-chain swap pairs (ETH <-> BSC, etc.) are routed to other providers
inside the same `MultiSwap` framework — notably `AllBridgeMultiSwapProvider`,
`ThorChainMultiSwapProvider`, and `MayaMultiSwapProvider`. 1Inch is wired
in as one same-chain DEX aggregator among several.

Below is a faithful description of the components that *would* be involved
if 1Inch supported cross-chain (which it does not in this codebase), plus
how the same-chain 1Inch swap path actually wires the quote / build /
sign / send roles.

## Evidence for "no cross-chain via 1Inch"

File `/Users/ant013/Ios/bench-vanilla/Unstoppable/Unstoppable/Modules/MultiSwap/Providers/OneInchMultiSwapProvider.swift`,
`supports(...)`:

```swift
override func supports(tokenIn: MarketKit.Token, tokenOut: MarketKit.Token) -> Bool {
    guard tokenIn.blockchainType == tokenOut.blockchainType else {
        return false
    }
    switch tokenIn.blockchainType {
    case .ethereum, .binanceSmartChain, .polygon, .avalanche,
         .optimism, .arbitrumOne, .gnosis, .fantom, .base: return true
    default: return false
    }
}
```

The same `MultiSwapProviderManager` (which discovers providers) registers
1Inch alongside AllBridge, ThorChain, Maya, Uniswap V3, PancakeSwap V3 —
selection happens in the UI based on each provider's `supports(...)`
verdict for the user-picked pair.

## Who does what (responsibilities)

- **Quote**: `OneInchMultiSwapProvider.quote(...)` (lines 45-70 of the file) calls `OneInchKit.Kit.quote(networkManager:chain:fromToken:toToken:amount:fee:)`. The kit hits 1Inch's REST API on the chain identified by `chain` (a single chain). Returns `OneInchKit.Quote` whose `amountOut` is wrapped in an `EvmMultiSwapQuote`.
- **Build route / build transaction**: `OneInchMultiSwapProvider.confirmationQuote(...)` (lines 72-130) calls `OneInchKit.Kit.swap(...)`. The 1Inch backend returns an `OneInchKit.Swap` containing a fully-built `transaction` (`to`, `value`, `data`, `gasLimit`, `gasPrice`). The provider wraps it in `TransactionData` via the local extension `OneInchKit.Swap.transactionData` and packages it as `EvmSwapFinalQuote`.
- **Fee / gas estimation**: `EvmFeeEstimator.estimateFee(...)` is invoked with the built `transactionData` and the user's `gasPriceData`.
- **Spender approval target**: `OneInchMultiSwapProvider.spenderAddress(chain:)` returns `OneInchKit.Kit.routerAddress(chain:)` — the 1Inch router on that single chain. ERC-20 approval flows through `BaseEvmMultiSwapProvider`'s `allowanceState(...)`.
- **Signing + broadcast**: `MultiSwapSendHandler.send(data:)` (lines 108-140) obtains the per-chain `EvmKitWrapper` via `evmBlockchainManager.evmKitManager(blockchainType: tokenIn.blockchainType).evmKitWrapper` and calls `evmKitWrapper.send(transactionData:gasPrice:gasLimit:privateSend:nonce:)`. `EvmKitWrapper` owns the signer for that chain; it signs the raw transaction with the active account's EVM private key and broadcasts via `EvmKit.Kit`.
- **MEV protection**: optional; for 1Inch path it relies on the base default `mevProtectionAllowed = false` (1Inch provider does not override).
- **Recording**: `MultiSwapSendHandler.send(...)` writes a `Swap` row via `swapHistoryManager.save(swap:)` and via `OneInchMultiSwapProvider.track(swap:)` posts a tracking payload to the U-Swap tracking endpoint.

```

       |---------------------------------------> 1Inch REST API
       |    EvmMultiSwapQuote <----------------+

       |---------------------------------------> 1Inch REST API (swap endpoint)
       |    EvmSwapFinalQuote(transactionData, gasPrice, gasLimit, nonce, slippage)
       v

       |
       |  evmBlockchainManager.evmKitManager(blockchainType).evmKitWrapper
       v

       |
       v
swapHistoryManager.save(Swap)
OneInchMultiSwapProvider.track(swap)  --> USwapMultiSwapProvider.track(...)
```

Key takeaway re the prompt's example (ETH -> BNB):
`OneInchMultiSwapProvider.supports(.ethereum, .binanceSmartChain) == false`,
so 1Inch is never selected for it. The Multi-Swap UI offers the user
`AllBridgeMultiSwapProvider` or `ThorChainMultiSwapProvider` /
`MayaMultiSwapProvider` instead — those are the real cross-chain
components in this codebase. If you actually meant "describe cross-chain
swap in the wallet" rather than "describe 1Inch cross-chain", the same
`IMultiSwapProvider` / `MultiSwapProviderManager` / `MultiSwapSendHandler`
spine applies, with the provider implementation swapped for one of those
three.
