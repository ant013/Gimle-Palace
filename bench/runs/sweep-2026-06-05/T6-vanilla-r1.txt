## Task T6 — Add USDC (Ethereum mainnet) to the default ERC-20 whitelist

### Where the whitelist lives

In this codebase the "list of pre-approved ERC-20 tokens shown by default in the wallet" is the hardcoded `tokenQueries` array inside `CreateAccountViewModel.activateDefaultWallets(account:)` at `/Users/ant013/Ios/bench-vanilla/Unstoppable/Unstoppable/Modules/CreateAccount/CreateAccountViewModel.swift`. That array is iterated through `MarketKit.tokens(queries:)`, and each resolved token is saved as a `Wallet` for the freshly created account — exactly the "default" tokens a brand-new user sees on the wallet screen.

Before the change it contained only **USDT on Ethereum** (`0xdac17f958d2ee523a2206206994597c13d831ec7`) and **USDT on TRC-20**; ETH/BNB/BTC/XMR/TRX were native entries on the same list. USDC was absent.

Note: there is a related but distinct list — `StablecoinRegistry` (Core/Abstraction/Config/StablecoinRegistry.swift) — that already contains USDC Ethereum (`0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48`). That registry is scoped to the ERC-4337 gas-abstraction (Barz / passkey-owned) flow, not the default mnemonic-account wallet list, so this task targets `CreateAccountViewModel`.

Two changes folded into one edit:
1. Hoisted the inline array into a `static let defaultWalletTokenQueries` so it is named, documented as the whitelist, and addressable from tests (no need to construct the full VM).
2. Appended the USDC entry for `BlockchainType.ethereum` with the requested checksum-lowercased address `0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48`. The casing matches the existing USDT entry on the same chain and aligns with `StablecoinRegistry`, so equality checks (which the registry comments call out as case-insensitive on the EVM side) stay consistent.

### New test (covers the change)

New file `/Users/ant013/Ios/bench-vanilla/Unstoppable/Tests/Modules/CreateAccount/CreateAccountDefaultTokenQueriesTests.swift`:

```swift
import MarketKit
import Testing
@testable import Unstoppable

struct CreateAccountDefaultTokenQueriesTests {
    // USDC on Ethereum mainnet must be part of the whitelist of pre-approved tokens
    // activated for every freshly created mnemonic account.
    @Test
    func includesUsdcOnEthereumMainnet() {
        let usdcEthereum = TokenQuery(
            blockchainType: .ethereum,
            tokenType: .eip20(address: "0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48")
        )

        #expect(CreateAccountViewModel.defaultWalletTokenQueries.contains { matches($0, usdcEthereum) })
    }

    // Sanity: pre-existing whitelist entries (USDT on Ethereum and TRC-20 USDT) stay in place.
    @Test
    func keepsExistingErc20Whitelist() {
        let usdtEthereum = TokenQuery(
            blockchainType: .ethereum,
            tokenType: .eip20(address: "0xdac17f958d2ee523a2206206994597c13d831ec7")
        )
        let usdtTron = TokenQuery(
            blockchainType: .tron,
            tokenType: .eip20(address: "TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t")
        )

        let queries = CreateAccountViewModel.defaultWalletTokenQueries
        #expect(queries.contains { matches($0, usdtEthereum) })
        #expect(queries.contains { matches($0, usdtTron) })
    }

    // The whitelist must remain duplicate-free (otherwise MarketKit will resolve and
    // activate the same wallet twice on account creation).
    @Test
    func hasNoDuplicateEntries() {
        let ids = CreateAccountViewModel.defaultWalletTokenQueries.map(\.id)
        #expect(Set(ids).count == ids.count)
    }

    private func matches(_ lhs: TokenQuery, _ rhs: TokenQuery) -> Bool {
        lhs.blockchainType == rhs.blockchainType && lhs.tokenType == rhs.tokenType
    }
}
```

Test file follows the existing convention (Swift Testing `struct`/`@Test`, `@testable import Unstoppable`, `#expect(...)`) seen in `Unstoppable/Tests/Models/AccountTypePasskeyOwnedTests.swift` and `Unstoppable/Tests/Modules/CreateSmartAccount/CreateSmartAccountServiceTests.swift`. It lives under `Unstoppable/Tests/Modules/CreateAccount/` mirroring the source layout.
