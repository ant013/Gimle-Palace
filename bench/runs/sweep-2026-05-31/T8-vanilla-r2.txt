## Silent-failure spot

**File:** `/Users/ant013/Ios/bench-vanilla/Unstoppable/Unstoppable/Modules/Send/Fee/SendFeeViewModel.swift`, `sync(state:)`, the `.failed` case (lines 41-46 before patch).

### Trace of the silent path (insufficient UTXOs)

When the user enters an amount that — together with the network fee — exceeds the sum of selectable UTXOs (or has hand-picked a UTXO subset via Output Selector that cannot cover `amount + fee`):

1. `SendBitcoinAdapterService.update(...)` (`Modules/Send/Platforms/Bitcoin/SendBitcoinAdapterService.swift:166-198`) builds `SendParameters` with `unspentOutputs: customOutputs` and calls `adapter.sendInfo(params:)`.
2. BitcoinCore throws `BitcoinCoreErrors.SendValueErrors.notEnough`. Caught → `sendInfoState = .failed(error)` (line 183).
3. `feeState = sendInfoState.map(\.fee)` propagates the failure (line 72).
4. `SendFeeService.sync(feeState:)` (`Modules/Send/Fee/SendFeeService.swift:50-57`) sets `state = .failed(error)`.
5. **`SendFeeViewModel.sync(state:)` `.failed` case discards the error entirely** and shows only `.error(text: "n/a".localized)` in the tiny fee row.

The user sees a red `"n/a"` next to "Fee", the Send button is disabled, and no caution banner explains why. `SendAmountCautionService` is wired to `availableBalanceService` only (and only against the bare amount), so a UTXO-subset that covers the amount but not amount+fee never triggers `insufficientBalance` there either.

The newer `SendNew` module (`Modules/SendNew/UtxoSendHelper.swift` + `BitcoinSendHandler.swift`) does handle this — but the legacy `Modules/Send/` Bitcoin pipeline (`SendBitcoinViewController` + `SendFeeViewModel`) is still wired in `SendModule.swift:111` and is the silent one.

### Why this is the smallest correct patch

- Touches one file, one switch case, ~5 effective lines.
- Re-uses the project's existing error-surfacing pattern (`error.convertedError.smartDescription`) — same idiom already used in `MoneroSendHelper`, `StellarSendHelper`, `TronSendHelper`, `TonSendHelper`, `ZanoSendHelper`, `SendEip1155ViewModel`, `SendTronViewModel`.
- `BitcoinCoreErrors.SendValueErrors` is itself an `Error`; if no `ConvertibleError` extension matches, `convertedError` falls through to `self` (per `Models/ConvertedError.swift:18-25`), and `smartDescription` formats it.
- The error now appears in red in the fee row instead of `n/a`, so the user has a concrete diagnostic (e.g. localized "not enough") in the place they were already looking for the fee.

### Optional follow-up (NOT applied; out of "smallest-patch" scope)

A more polished UX would also pipe `sendInfoState` into `SendAmountCautionService` and emit a proper `.insufficientBalance(...)` banner — but that requires adding a property + setter + subscription in `SendAmountCautionService` and a new wiring line in `SendModule.swift`, and is not necessary to fix the silent-failure complaint.
