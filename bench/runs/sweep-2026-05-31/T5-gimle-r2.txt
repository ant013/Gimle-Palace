## Critical correction to task premise

In `unstoppable-wallet-ios` (bench-gimle worktree), **1Inch does NOT perform cross-chain swaps**. `OneInchMultiSwapProvider.supports(tokenIn:tokenOut:)` (`Unstoppable/Unstoppable/Modules/MultiSwap/Providers/OneInchMultiSwapProvider.swift:34-43`) explicitly returns `false` whenever `tokenIn.blockchainType != tokenOut.blockchainType`. The bundled `OneInchKit.Swift` package (`/Users/ant013/Ios/HorizontalSystems/OneInchKit.Swift/Sources/OneInchKit/Kit.swift`) only exposes single-chain `quote(chain:...)` and `swap(chain:...)` — there is no Fusion+ / cross-chain SDK call anywhere under `Sources/OneInchKit/` or in the `WalletCore/BackCompatibility/OneInchKit.swift` shim.

Therefore an "Ethereum → BSC" swap in this app cannot be routed through 1Inch. It is routed through cross-chain providers (ThorChain, Maya, AllBridge), which are registered alongside 1Inch in `MultiSwapProviderManager` but selected by the `supports()` filter at quote time.

I describe BOTH below: (A) the 1Inch same-chain pipeline (what 1Inch actually does in this codebase, e.g. ETH→USDC on Ethereum, or BNB→CAKE on BSC), and (B) the cross-chain pipeline that handles the Ethereum↔BSC case the task references.

### Quote → Sign → Build responsibility breakdown

- **Quotes** are produced by `OneInchMultiSwapProvider.quote()`, which delegates to `OneInchKit.Kit.quote()` (HTTP call to 1inch.io). Returned as `EvmMultiSwapQuote` (file `Modules/MultiSwap/Providers/EvmMultiSwapQuote.swift`).
- **Builds the route / unsigned transaction** when the user reaches the confirmation screen: `OneInchMultiSwapProvider.confirmationQuote()` -> `OneInchKit.Kit.swap()` returns `OneInchKit.Swap` whose `transaction` carries `to`, `value`, `data` (the encoded 1Inch router call), `gasPrice`, `gasLimit`. Wrapped into a `TransactionData` (extension at OneInchProvider lines 179–183) and packed into `EvmSwapFinalQuote`.
- **Signs** the raw transaction: `EvmKitWrapper.send(...)` calls `Signer.signature(rawTransaction:)` then broadcasts via `EvmKit.Kit.send(rawTransaction:signature:)`. If MEV protection is enabled it broadcasts through `MerkleTransactionAdapter` instead. The user's private key/mnemonic is held by `Signer`, not by `OneInchMultiSwapProvider`.

## B. Real Ethereum → BSC cross-chain pipeline (what 1Inch doesn't do here)

Same outer shell (`MultiSwapViewModel` → `MultiSwapSendHandler` → `EvmKitWrapper`) — only the provider implementation differs. The candidate cross-chain providers actually selected:

| Provider class | File |
|---|---|
| `ThorChainMultiSwapProvider : BaseThorChainMultiSwapProvider` | `Modules/MultiSwap/Providers/ThorChain/ThorChainMultiSwapProvider.swift`, base at `BaseThorChainMultiSwapProvider.swift` |
| `MayaMultiSwapProvider : BaseThorChainMultiSwapProvider` | `Modules/MultiSwap/Providers/ThorChain/MayaMultiSwapProvider.swift` |
| `AllBridgeMultiSwapProvider` | `Modules/MultiSwap/Providers/AllBridgeProvider/AllBridgeMultiSwapProvider.swift` |

How the cross-chain providers behave differently from 1Inch:

- `supports()` consults a remotely-fetched asset map (`assetMap` synced from `/pools` endpoint, e.g. ThorChain) — pairs only show as supported if BOTH ends exist in the pool list (`BaseThorChainMultiSwapProvider.swift:55-57`).
- `quote()` calls the provider's REST API (`networkManager.fetch(url: "\(baseUrl)/quote/swap", parameters:)`, lines 227–264). The response (`SwapQuote`) carries `inboundAddress`, `router`, `memo`, `expectedAmountOut`, etc.
- `confirmationQuote()` builds the EVM tx that sends source-chain funds INTO ThorChain's inbound address:
  - **native asset path** (`tokenIn.type == .native`): plain `TransactionData(to: inboundAddress, value: amount, input: memoBytes)` — lines 96–100.
  - **ERC20 path**: encodes a call to `DepositWithExpiryMethod(inboundAddress, asset, amount, memo, expiry)` against the ThorChain `router` contract — lines 102–113, 425–447.
- The destination payout on BSC (or any other chain) is performed off-chain by ThorChain's network and arrives at `toAddress` (resolved by `DestinationHelper.resolveDestination`, lines 266–272), which defaults to the wallet's own BSC receive address but can be a recipient override.
- Signing path is **identical to the 1Inch case**: `MultiSwapSendHandler.send()` (line 108) sees an `EvmSwapFinalQuote`, calls `EvmKitWrapper.send(...)` against the **source-chain** EvmKit (Ethereum). The BSC chain is never signed against by the user — ThorChain bridge nodes mint/release the output.

So in this codebase the actor map for Ethereum→BSC is:

- **Quotes** = `ThorChainMultiSwapProvider` (or Maya / AllBridge), hitting THORChain Midgard / AllBridge API.
- **Builds the route (the source-chain tx)** = same provider's `confirmationQuote()` — either a raw `TransactionData` for native ETH, or a `depositWithExpiry(...)` call to the THORChain router for ERC20s. The "destination route" itself lives off-chain in the cross-chain network.
- **Signs** = the user's Ethereum `Signer` inside `EvmKitWrapper.send()` (`Core/Managers/EvmKitManager.swift:216-229`).
- **Broadcasts** = `EvmKit.Kit.send` (or `MerkleTransactionAdapter.send` for MEV-protected).
- **Tracks** = `BaseThorChainMultiSwapProvider.track()` (lines 209–225) -> `USwapMultiSwapProvider.track(swap:parameters:networkManager:)`.
