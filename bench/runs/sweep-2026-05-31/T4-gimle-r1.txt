## How it gets its dependencies — pattern: manual constructor injection via a hand-rolled factory + composition root

There is no third-party DI container (no Swinject, Resolver, Needle, etc.). The project uses the classic UW-iOS pattern: a single composition-root file (`Core.swift`) instantiates managers and hands them to factories; factories then instantiate per-wallet adapters on demand.

1. **`MoneroAdapter`'s direct dependencies** are produced inside `AdapterFactory` (not injected from outside) at the moment a wallet needs an adapter:
   - `wallet` — passed through from the caller (`AdapterManager` → `adapter(wallet:)`).
   - `restoreSettings: RestoreSettings` — read from the injected `RestoreSettingsManager` via `restoreSettingsManager.settings(accountId:blockchainType:)`.
   - `node: Node` — read from the injected `MoneroNodeManager` via `moneroNodeManager.node(blockchainType: .monero).node`.

2. **`AdapterFactory` itself uses constructor injection**. Its `init` (`AdapterFactory.swift:24-42`) takes 13 collaborators as constructor parameters and assigns them to `private let` stored properties — `EvmBlockchainManager`, `EvmSyncSourceManager`, `MoneroNodeManager`, `BtcBlockchainManager`, `TronKitManager`, `TonKitManager`, `StellarKitManager`, `ZanoKitManager`, `SolanaKitManager`, `RestoreSettingsManager`, `CoinManager`, `SpamWrapper`, `EvmLabelManager`. It conforms to `IAdapterFactory`.

3. **The composition root is `Core.swift`** (`Unstoppable/Unstoppable/Core/Core.swift:318`). The `Core` class (a singleton accessed as `Core.shared`) builds the dependency graph at app startup and wires `AdapterFactory` like this:

```swift
let adapterFactory = AdapterFactory(
    evmBlockchainManager: evmBlockchainManager,
    evmSyncSourceManager: evmSyncSourceManager,
    moneroNodeManager: moneroNodeManager,
    btcBlockchainManager: btcBlockchainManager,
    tronKitManager: tronKitManager,
    ...
    spamWrapper: spamWrapper,
    evmLabelManager: evmLabelManager
)
let adapterEngine = AdapterManager(
    adapterFactory: adapterFactory,
    walletManager: walletManager
)
adapterManager = AppAdapterManager(engine: adapterEngine, ...)
```

4. **Trigger / lifecycle**: `AdapterManager.adapter(for: wallet)` (delegated from `AppAdapterManager`) calls `adapterFactory.adapter(wallet:)` when a wallet appears, which executes the `(.native, .monero)` `switch` arm above. The constructed adapter is owned by `AdapterManager` and consumed from the rest of the app via the protocols `MoneroAdapter` conforms to: `IAdapter`, `IBalanceAdapter`, `ITransactionsAdapter`, `IDepositAdapter` (plus `MoneroKitDelegate` for kit callbacks).

The only other `MoneroAdapter` references are:
- `AppAdapterManager.swift:133` — downcasts an existing adapter to call `.restart()` (not a construction).
- `KitCleaner.swift:25` — calls the static `MoneroAdapter.clear(except:)` (not a construction).
