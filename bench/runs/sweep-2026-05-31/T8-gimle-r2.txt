## Silent failure location
`Unstoppable/Unstoppable/Modules/SendNew/BitcoinSendHandler.swift:30-59` — `sendData(transactionSettings:)`.

## Root cause chain
1. `BitcoinBaseAdapter.availableBalance(params:)` at `Unstoppable/Unstoppable/Core/Adapters/BitcoinBaseAdapter.swift:298-301` swallows `abstractKit.maxSpendableValue(params:)` errors with `(try? ...) ?? 0`. When UTXOs cannot cover even the fee, it returns `0` instead of throwing.
2. In `BitcoinSendHandler.sendData`, when `decimalValue == balance` (user tapped MAX or balance equals amount), the code overwrites `params.value` with `convertToSatoshi(value: 0) = 0`.
3. Originally, `adapter.sendInfo(params:)` is then unconditionally invoked with value=0. Depending on BitcoinCore behavior, it returns `fee = 0` with no thrown error — leaving `transactionError = nil` and `fee != nil`, so `SendData.canSend = true` and `cautions(...)` emits nothing. User sees no error.

## Smallest patch (working-tree diff, not committed)

```diff
--- a/Unstoppable/Unstoppable/Modules/SendNew/BitcoinSendHandler.swift
+++ b/Unstoppable/Unstoppable/Modules/SendNew/BitcoinSendHandler.swift
@@ -42,11 +42,19 @@ extension BitcoinSendHandler: ISendHandler {
                 params.value = adapter.convertToSatoshi(value: adapter.availableBalance(params: params))
             }
 
-            do {
-                let sendInfo = try adapter.sendInfo(params: params)
-                fee = sendInfo.fee
-            } catch {
-                transactionError = error
+            if (params.value ?? 0) <= 0 {
+                // availableBalance(params:) returned 0 (or value was cleared) — UTXOs cannot
+                // fund any send at this fee rate. Surface a user-visible "insufficient balance"
+                // caution instead of silently producing fee=0 / canSend=true (notEnough is
+                // mapped by UtxoSendHelper.caution to "fee_settings.errors.insufficient_balance").
+                transactionError = BitcoinCoreErrors.SendValueErrors.notEnough
+            } else {
+                do {
+                    let sendInfo = try adapter.sendInfo(params: params)
+                    fee = sendInfo.fee
+                } catch {
+                    transactionError = error
+                }
             }
         }
```

## Why this is minimal and correct
- 8 added lines; modifies one file; introduces no new error types, no new localized strings, no UI changes.
- Reuses existing `BitcoinCoreErrors.SendValueErrors.notEnough` — analog at `Unstoppable/Unstoppable/Modules/SendNew/ZcashSendHelper.swift:19` does the same pattern (insufficient-balance → return notEnough).
- Reuses existing mapping in `Unstoppable/Unstoppable/Modules/SendNew/UtxoSendHelper.swift:33-37`: `.notEnough` → `fee_settings.errors.insufficient_balance` localized title + `fee_settings.errors.insufficient_balance.info` body. User caution surfaces automatically through `BitcoinSendHandler.SendData.cautions(...)` (lines 119-127).
- Assignment idiom matches `Unstoppable/Unstoppable/Modules/MultiSwap/Providers/ThorChain/MayaMultiSwapProvider.swift:102` (`transactionError = BitcoinCoreErrors.SendValueErrors.X`).
- After the patch: `transactionError` is set → `fee` stays nil → `SendData.canSend` returns false (line 107-109) → Send button disabled and caution shown.
