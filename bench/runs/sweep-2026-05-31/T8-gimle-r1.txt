## Silent-failure location

`Unstoppable/Unstoppable/Modules/SendNew/BitcoinSendHandler.swift` — `BitcoinSendHandler.sendData(transactionSettings:)`, the max-amount branch (lines 36-51 pre-patch).

## Why it is silent

1. When user sends max amount, the handler calls `adapter.availableBalance(params:)`.
2. `BitcoinBaseAdapter.availableBalance(params:)` (line 299 of BitcoinBaseAdapter.swift) wraps `abstractKit.maxSpendableValue(params:)` in `try?`, so when UTXOs cannot fund a spend (insufficient/dust/fragmented), it returns `0` instead of throwing.
3. `params.value` is then set to `0` (or stays nil).
4. `adapter.sendInfo(params:)` is called with `value == 0`; either it returns `SendInfo` with `fee == 0` (no throw), or in the no-substitution path the surfaced error is a `dust(...)`, not the user-facing "insufficient balance" wording.
5. Result: `SendData(fee: 0, transactionError: nil)` → `canSend = fee != nil && transactionError == nil` → **true**, with `cautions(...)` returning `[]` (it guards on `transactionError`). The Send screen shows no error and the slide-to-send button remains enabled.

Compare with sibling adapters (`MoneroSendHandler`, `SolanaSendHandler`, etc.) — they all pre-check balance and emit a `transactionError` so `UtxoSendHelper.caution` / equivalent surfaces "Insufficient balance". The same convention is already used inside the codebase via `BitcoinCoreErrors.SendValueErrors.dust(...)` in `MayaMultiSwapProvider.swift:101` and `USwapMultiSwapProvider.swift:705`.

## How it surfaces the error

`BitcoinCoreErrors.SendValueErrors.notEnough` is already handled by `UtxoSendHelper.caution(transactionError:feeToken:)` (UtxoSendHelper.swift:34-37) which produces a `CautionNew` titled `fee_settings.errors.insufficient_balance` ("Insufficient balance") with the body `fee_settings.errors.insufficient_balance.info` keyed on the coin code. The existing `BitcoinSendHandler.SendData.cautions(baseToken:currency:rates:)` already appends this caution, and `canSend` becomes false because `transactionError != nil`, disabling the send slider.
