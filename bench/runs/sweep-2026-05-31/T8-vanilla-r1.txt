File: /Users/ant013/Ios/bench-vanilla/Unstoppable/Unstoppable/Modules/Send/Platforms/Bitcoin/SendBitcoinAdapterService.swift (lines 177-184)

```swift
do {
    if let adapter = self?.adapter {
        let sendInfo = try adapter.sendInfo(params: params)
        self?.sendInfoState = .completed(sendInfo)
    }
} catch {
    self?.sendInfoState = .failed(error)  // <-- error captured but never surfaced
}
```

When `adapter.sendInfo` throws `BitcoinCoreErrors.SendValueErrors.notEnough` (selected UTXOs cannot cover amount + fee), `sendInfoState` becomes `.failed(error)`. Downstream:
- `feeState = sendInfoState.map(\.fee)` becomes `.failed(error)`.
- `SendFeeViewModel.sync(state:)` (Modules/Send/Fee/SendFeeViewModel.swift:41) renders the fee cell as the bare string "n/a" — no `caution`, no title, no error text.
- `SendBitcoinService.syncState()` (Modules/Send/Platforms/Bitcoin/SendBitcoinService.swift:65) never inspects `sendInfoState`, so `state` stays `.ready` whenever `amount <= availableBalance` and the address/fee-rate are valid. The proceed button stays enabled.

Net effect: the user enters an amount that almost equals their balance (or selects custom UTXOs that don't cover the fee), sees fee = "n/a", gets no explanation, but the proceed button looks active. (Note: the SendNew path in `Modules/SendNew/BitcoinSendHandler.swift` already surfaces this error via `UtxoSendHelper.caution` — only the legacy SendBitcoin* path is silent.)

Smallest patch
==============
Bridge the existing `ISendInfoValueService.sendInfoStateObservable` into the existing `SendAmountCautionService`, so a failed `sendInfo` with `SendValueErrors.notEnough` produces the same `.insufficientBalance` caution that the amount-vs-balance check already produces. That caution is already rendered by `SendAmountCautionViewModel` ("send.amount_error.balance") and already gates the proceed button via `SendBitcoinService.syncState`.
