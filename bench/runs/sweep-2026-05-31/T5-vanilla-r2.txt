## 1Inch in unstoppable-wallet-ios — does it do cross-chain?

**Short answer: NO.** The current iOS codebase integrates 1Inch only as a **same-chain EVM aggregator**, not as a cross-chain bridge. There is no integration with 1Inch Fusion+ / 1Inch Cross-Chain Swap. The hard gate is in `OneInchMultiSwapProvider.supports(...)` which immediately returns `false` whenever `tokenIn.blockchainType != tokenOut.blockchainType`:

```swift
// /Users/ant013/Ios/bench-vanilla/Unstoppable/Unstoppable/Modules/MultiSwap/Providers/OneInchMultiSwapProvider.swift
override func supports(tokenIn: MarketKit.Token, tokenOut: MarketKit.Token) -> Bool {
    guard tokenIn.blockchainType == tokenOut.blockchainType else { return false }
    switch tokenIn.blockchainType {
    case .ethereum, .binanceSmartChain, .polygon, .avalanche,
         .optimism, .arbitrumOne, .gnosis, .fantom, .base: return true
    default: return false
    }
}
```

So for the literal "ETH→BNB chain via 1Inch" request, the wallet would *not* route through 1Inch at all. Cross-chain stable-asset swaps are routed through **AllBridge** (`AllBridgeMultiSwapProvider`), and cross-chain native swaps go through **ThorChain** (`ThorChainMultiSwapProvider`) or **Maya** (`MayaMultiSwapProvider`) — they live alongside `OneInchMultiSwapProvider` under the same `IMultiSwapProvider` protocol.

Below is the actual component map for the 1Inch (same-chain EVM) path, which the user can compare against to confirm there is no cross-chain branch.

### Role per class (who does what)

| Concern | Class | Notes |
|---|---|---|
| Provider registry / "which providers are enabled" | `MultiSwapProviderManager` | Calls `/v1/providers`; default list includes `OneInchMultiSwapProvider.id`. |
| Provider instantiation | `SwapProviderFactory` | `OneInchMultiSwapProvider(kit: OneInchKit.Kit.instance(apiKey: AppConfig.oneInchApiKey))`. |
| Eligibility (chain pairing) | `OneInchMultiSwapProvider.supports(tokenIn:tokenOut:)` | **Rejects all cross-chain pairs.** Lists the 9 supported EVM chains. |
| Indicative quote | `OneInchMultiSwapProvider.quote(...)` → `OneInchKit.Kit.quote(...)` | Wraps result in `EvmMultiSwapQuote` plus `allowanceState`. |
| Build the route + tx payload (the "router" call) | `OneInchMultiSwapProvider.confirmationQuote(...)` → `OneInchKit.Kit.swap(...)` | Returns `OneInchKit.Swap` whose `.transaction` carries `to`/`value`/`data`/`gasLimit`/`gasPrice`. The extension at the bottom of `OneInchMultiSwapProvider.swift` adapts it into `EvmKit.TransactionData`. |
| ERC20 allowance / approve gate | `MultiSwapAllowanceHelper` (used via `BaseEvmMultiSwapProvider.allowanceState`) | `spenderAddress(chain:)` returns `OneInchKit.Kit.routerAddress(chain:)`. |
| Slippage & recipient settings | `MultiSwapSendHandler.menuItems` + `MultiSwapSlippageView` / `MultiSwapRecipientView` | Slippage is forwarded into `OneInchKit.Kit.swap(... slippage:)`. |
| Gas estimation | `EvmFeeEstimator.estimateFee(...)` | Reused for all EVM providers. |
| Confirmation packaging | `EvmSwapFinalQuote` (subclass of `SwapFinalQuote`) | Carries `transactionData`, `gasPrice`, `evmFeeData`, `nonce`. |
| **Signs the transaction** | `EvmKitWrapper.send(...)` → `signer.signature(rawTransaction:)` where `signer: Signer?` is owned by `EvmKitWrapper` (constructed by `EvmKitManager`). Broadcast goes through `evmKit.send(...)` or `merkleTransactionAdapter.send(...)` (MEV-protected path). |
| MEV protection toggle | `BaseEvmMultiSwapProvider.mevProtectionAllowed(...)` → `MerkleTransactionAdapter.allowProtection(...)`, consumed in `MultiSwapSendHandler.send` via `MevProtectionHelper.isActive`. |
| History + analytics ping | `MultiSwapSendHandler` saves a `Swap` via `swapHistoryManager`; `OneInchMultiSwapProvider.track(swap:)` delegates to `USwapMultiSwapProvider.track(...)`. |

This legacy path is also same-chain-only — it uses the identical `OneInchKit.Kit` whose endpoints are per-chain.

### How an actual ETH→BNB-chain swap is routed in this app (for contrast)

Same `IMultiSwapProvider` protocol, but a different concrete provider — `AllBridgeMultiSwapProvider` at `/Users/ant013/Ios/bench-vanilla/Unstoppable/Unstoppable/Modules/MultiSwap/Providers/AllBridgeProvider/AllBridgeMultiSwapProvider.swift` — which (a) detects `crosschain = tokenIn.blockchainType != tokenOut.blockchainType`, (b) calls the AllBridge `bridge` endpoint (vs `swap` for same-chain), and (c) on the EVM source side ultimately funnels the built `TransactionData` through the same `EvmKitWrapper.send(...) → Signer.signature(...) → EvmKit.Kit.send(...)` signing/broadcast path used by 1Inch. Native cross-chain swaps (e.g. BTC↔ETH) similarly go through `ThorChainMultiSwapProvider` / `MayaMultiSwapProvider`.

### Bottom line for the task
- `OneInchMultiSwapProvider` quotes via `OneInchKit.Kit.quote`, builds the route via `OneInchKit.Kit.swap`, uses `OneInchKit.Kit.routerAddress` for ERC20 approvals, and hands the resulting `TransactionData` to `EvmKitWrapper`, where `Signer` does the signing. It deliberately refuses any pair whose two tokens are on different chains, so there is no 1Inch ETH↔BNB-chain flow in unstoppable-wallet-ios.
